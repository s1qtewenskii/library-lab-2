# Вопросы к защите лабораторной работы № 2

1. **Что такое регулярное выражение?** Шаблон, который описывает набор строк.
   По нему можно проверить строку или найти фрагменты текста.
2. **Где применяются регулярные выражения?** При проверке форматов ввода,
   поиске данных в тексте, разделении строк и замене фрагментов.
3. **Основной синтаксис в Python.** Модуль `re`; `[0-9]` — цифра,
   `.` — любой символ, кроме перевода строки по умолчанию, `*` — от нуля повторов,
   `+` — от одного, `?` — ноль или один, `{2}` — ровно два,
   `|` — выбор, `()` — группа, `^` и `$` — границы строки.
   У `$` есть особенность: он может совпасть перед завершающим переводом строки.
   Запись `r"..."` сохраняет обратные слеши для регулярного выражения.
4. **`re.match()`** Ищет совпадение только с начала строки; остаток строки может
   не совпасть. В этой работе `fullmatch()` проверяет всю строку целиком.
5. **`re.search()`** Ищет первое совпадение в любом месте строки.
   Возвращает объект `Match` или `None`. Текст совпадения доступен через `group()`.
6. **`re.findall()`** Возвращает список всех непересекающихся совпадений.
   Если в шаблоне есть захватывающие группы, возвращает их содержимое;
   поэтому в работе используется незахватывающая группа `(?:...)`.
7. **`re.split()`** Разделяет строку по регулярному выражению.
   Например, `re.split(r"[,;]", "a,b;c")` дает список из трех частей.
8. **`re.sub()`** Заменяет совпадения: `re.sub(r"[0-9]", "*", "a12")` дает `a**`.
9. **`re.compile()`** Создает объект регулярного выражения для повторного
   использования. Его методы: `fullmatch()`, `search()`, `findall()` и другие.
10. **HTTP-запросы в Python.** Можно использовать `requests.get(url, timeout=10)`
    или стандартный `urllib.request`. GET получает данные, POST обычно отправляет.
    В этой работе выбран поиск в локальном файле, HTTP-запросов нет.
11. **Коды HTTP.** 2xx — успешный запрос, 3xx — перенаправление,
    4xx — ошибка запроса клиента, 5xx — ошибка сервера.
    Примеры: 200 — OK, 404 — Not Found, 500 — Internal Server Error.
12. **HTTP-ответ.** Содержит код состояния, заголовки и тело.
    У ответа `requests` есть `status_code`, `headers`, `text`, `content`;
    `raise_for_status()` вызывает исключение при кодах 4xx и 5xx.
13. **Открытие и закрытие файла.** `open()` открывает файл.
    Конструкция `with open(path, encoding="utf-8") as file:` закрывает его
    автоматически, в том числе при исключении.
14. **Чтение из файла.** `read()` читает все содержимое, `readline()` — одну строку.
    Также можно перебирать строки циклом `for line in file`.
15. **Запись в файл.** Режим `w` создает файл или стирает старое содержимое,
    `a` добавляет в конец. Метод `write()` записывает строку.
16. **Отладка и тестирование.** Отладчик позволяет ставить точки останова,
    выполнять код по шагам и смотреть значения переменных.
    Тесты автоматически сравнивают результат с ожидаемым.
17. **Виды тестов.** Модульные проверяют отдельные части программы,
    интеграционные — взаимодействие частей, системные — всю программу.
    Регрессионные проверки помогают заметить поломки после изменений.
18. **Unit-тестирование.** Проверка небольшой части кода на заранее выбранных
    данных. Нужны обычные, ошибочные и граничные случаи.
19. **Unit-тесты в Python.** В `unittest` тестовый класс наследуется от
    `TestCase`, названия методов начинаются с `test_`.
    Проверки: `assertEqual()`, `assertTrue()`, `assertFalse()`, `assertRaises()`.
    `subTest()` позволяет отдельно показать ошибку для каждого набора данных.
20. **Декораторы.** Функции, которые оборачивают другую функцию или класс
    и изменяют их поведение. Запись `@decorator` перед определением функции
    примерно соответствует `function = decorator(function)`.
    `patch()` из `unittest.mock` можно использовать и как декоратор,
    и через `with`, как в тестах меню.

## Что объяснить по своему варианту

- Почему часы разделены на диапазоны 00–19 и 20–23.
- Почему для полной проверки выбран `fullmatch()`, а не `search()`.
- Зачем при поиске нужны границы и почему нельзя взять только основной шаблон.
- Почему используются `[0-9]`, а не `\d`: нужны обычные цифры 0–9.
- Почему `9:00:00`, `24:00:00` и `12:60:00` не подходят.
- Как программа обрабатывает отсутствующий файл и неверную кодировку.
